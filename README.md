# 迎峰巡检与监测资料

本目录包含供能设施巡检、监测读数、天气预警及调度记录的合成样例。记录保留单位、观测窗口、设施代号和来源修订信息，供本地采集与联调使用。

> 所有站点、设备、读数、预警与调度安排均为虚构演练数据，不代表现实供能事故或真实调度决定。

## 快速开始

使用 Python 3.11 或更新版本，无第三方依赖：

```sh
# 基线契约检查 + 工作台测试
python3 -m unittest discover -s tests

# 文本工作台（默认取全部来源中最新采集时间作为判断时点）
python3 -m opsdesk

# 指定调度时点 / 时段 / 设施
python3 -m opsdesk --as-of 2026-12-18T06:30:00+08:00
python3 -m opsdesk --window 2026-12-18T05:00/2026-12-18T07:00 --asset HT-041
python3 -m opsdesk --area NORTH-3 --format json

# 本地只读页面
python3 -m opsdesk --serve --port 8765   # http://127.0.0.1:8765/
```

## 工作台解决的问题

### 1. 多来源接入与归一

- 监测、现场检查、气象预警、调度安排统一成带 `source_id` 的信封；缺字段或时序矛盾的记录不会被静默丢弃。
- 设备编号按台账 `aliases` 归一（如 `HT041` → `HT-041`）；无法解析的旧编号归入“未通过校验的来源”，并说明原因。
- 单位按量纲换算到基准单位（温度 °C、压力 kPa），例如 `bar` → `kPa`、`MPa` → `kPa`、`degC` → `C`。量纲不符或未登记的单位会拒收该读数，而不是猜测。
- 同一设施同一指标按 `revision` 取最新有效读数；`supersedes` 链标出被修正的历史读数。

### 2. 依据是否仍然有效

- **时效**：监测读数按设施阈值判断是否过期，现场检查按巡检周期判断，气象和调度记录按采集滞后判断。所有判断相对 `--as-of`，便于复盘。
- **时间切片**：只使用 `collected_at <= as-of` 的记录；历史时点不会看到后到修正。
- **检修口径**：处于检修窗口内的设施自动套用更严格的阈值，同一数值因此可能改变风险等级；检修前形成的读数会被标记需按新口径复测。
- **气象覆盖**：一条读数的有效窗口为 `[observed_at, observed_at + 采样周期]`。预警只有与这个窗口相交才算覆盖；提前生效但不覆盖读数窗口的预警会明确标为“未覆盖”，而不是想当然地视为有依据。

### 3. 缺资料与未核实项

- 缺口按三类分别记录，不混为“正常”：
  - **监测连续性**：无可用读数、读数过期、相邻读数间隔超过采样周期、同修订冲突。
  - **现场检查**：无检查记录、超过巡检周期。
  - **预警覆盖**：片区无预警、预警不覆盖读数窗口、仅部分覆盖。
- 没有可用读数时，设施结论为“待补证”，不会因现场或气象资料齐全就判成正常。
- 每台设施的 `gaps`、全局 `unverified` 表和 `recheck_queue` 都按设施与类别展开，便于值班员知道“缺的是哪一类依据”。

### 4. 后到修正与处置复核

- 处置安排记录 `basis_source_id` 或 `basis_revision`，指向形成判断时的监测版本。
- 后到的修正读数若取代了安排所依据的版本（或被修正的读数修订号落后于当前有效修订），该安排进入 **`needs_review` / `review_required`**，并在 `reasons` 中给出具体来源。
- 安排本身不会被撤销：原始 `state`、班组与派工信息保留，值班员可据此复核是否延续。
- 与该设备无关的处置安排保持原状态，不受影响。
- 调度安排的 `basis_chain` 按“监测读数 → 现场检查 → 气象预警 → 依据版本 → 处置”给出依据链。

### 5. 不同角色看到的内容

- **调度员**：设施结论、依据链、处置复核状态与有效状态。
- **巡检员**：`recheck_queue` 列出需要现场复测/补检的事项及原因；`unverified` 表列出资料缺口。
- **值班员**：可按设施、片区、时段筛选，并随时切换判断时点。

## 数据口径

- `fixtures/sources.json` 中 `meter-feed-a-r4` 故意使用旧单位 `degC` 与旧设备编号 `HT041`，用于演示归一。
- `meter-feed-legacy` 使用未登记的 `HT-041A`，用于演示拒收与人工核实。
- `DSP-220` 依据 `meter-feed-a`（修订 3），而该读数已被修订 4 取代，因此演示“安排进入复核但不撤销”。
- `DSP-221` 与 `HT-041` 无关，演示无关备援保持原状。
- 天气预警 `weather-forecast-e` 覆盖东二片区但生效时间晚于 `LN-220` 当前读数窗口，演示“有预警 ≠ 有覆盖”。

## 边界

- 本工作台是依据整理工具，不自动下发或撤销调度指令；`review_required` 仅提示人工复核。
- 阈值、巡检周期与检修窗口来自演示台账，不应直接用于现实调度。
